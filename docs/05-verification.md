# 검증 관점과 공개본의 한계

[← 포트폴리오](../README.md)

이 페이지는 주요 설계가 지켜야 할 조건과 검증 관점을 설명합니다. 소스 코드나 테스트 구현은 공개하지 않으며, 문서의 존재 자체를 테스트 통과나 성능 달성의 증거로 제시하지 않습니다.

## 설계별 확인 항목

| 설계 영역 | 확인할 조건 | 별도 검증이 필요한 범위 |
|---|---|---|
| 공유 길찾기 | 목표 표면·거리·방향이 지형의 연결 관계와 일치 | 다양한 실제 지형, 동적 변화, 대규모 부하 |
| 클래스별 적 풀 | 요청한 정확한 클래스만 반환하고 반납·취득 수가 일치 | 액터 수명주기와 네트워크 재활성화 |
| 서버 상점 | 오래된 요청·잘못된 인덱스를 거부하고 적용 실패 시 재화를 보존 | 실제 지연·패킷 손실·다중 클라이언트 |
| 카드 효과 | 모든 효과의 사전조건을 확인하고 획득 기록은 성공 뒤 반영 | 효과 간 간섭과 콜백 부작용 |
| 무기 스탯 캐시 | 입력이 바뀌면 최종 수치를 다시 계산 | 전체 무기 수정치·복제·장비 교체 경로 |

## 세 가지 회귀 검증 시나리오

### 정확한 클래스만 풀에서 반환

일반 적만 넣은 풀에서 엘리트 취득은 실패해야 합니다. 반대로 엘리트만 넣은 풀에서 일반 적 취득도 실패해야 합니다. 상속 관계가 있다는 이유로 다른 런타임 타입을 재사용하지 않는 계약을 확인합니다.

### 중복 구매와 효과 적용 실패

한 번 구매한 revision으로 다시 요청해도 잔액이 추가로 줄어들지 않아야 합니다. 잘못된 오퍼 인덱스도 잔액을 변경하면 안 됩니다. 효과 적용이 거부되면 차감한 돈을 돌려주고 기존 오퍼를 보존해야 합니다.

### 겹친 바닥에서 목표 표면 선택

합성된 2×1 그리드에 지면과 높은 데크를 배치합니다. 캐릭터의 발 높이를 기준으로 데크 표면을 선택하는지 확인합니다. 실제 월드를 구성하지 않고도 입력 데이터를 통해 층 선택의 경계 상황을 재현할 수 있습니다.

## 문서 검증과 실행 검증의 구분

공개 문서의 내부 링크와 코드 미포함 여부를 확인합니다. 이는 게임 실행 검증과 다릅니다. 이 저장소는 구조 설명과 다이어그램만 제공하므로 독립적으로 빌드하거나 게임을 실행할 수 없습니다.

이번 문서 정리 과정에서는 Unreal 빌드·Automation Tests·PIE·패키지 실행·성능 측정을 하지 않았습니다. Mermaid 다이어그램은 구조와 흐름을 설명하는 그림이며 게임 실행 결과가 아닙니다.

## 성능 결과를 설명할 때 필요한 조건

1,000개 적은 최악 상한 목표입니다. 실제 성능 자료에는 측정 버전, 엔진 버전, CPU/GPU, 해상도, 패키지 설정, 활성 적 수, 접속 인원, 호스트·클라이언트 구분, 프레임 시간과 네트워크 지표, 측정 시간을 함께 제시해야 합니다. 현재 공개본에는 재현 가능한 원시 측정 자료가 없어 성능 그래프나 개선율을 넣지 않았습니다.
