## 어떤 근거를 제공하는가

| 주장 | 이 저장소의 근거 | 의미하지 않는 것 |
|---|---|---|
| 공유 길찾기 구현이 있다 | `RunBFS`, `RebuildDropLinks` 발췌 | 모든 지형에서 정상 작동하거나 목표 FPS를 달성했다는 증명 |
| 클래스별 적 풀을 사용한다 | 풀 취득·축출 구현과 클래스 분리 테스트 발췌 | 모든 액터 수명주기와 네트워크 재활성화 검증 완료 |
| 오래된 상점 요청을 거부한다 | revision 검사, 거래 코드와 재요청 테스트 | 지연·손실·악성 패킷을 포괄하는 네트워크 보안 검증 |
| 카드 효과를 분리한다 | 효과 계약과 2단계 적용 루프 | 모든 사용자 정의 효과가 원자적으로 롤백됨 |
| 회귀 테스트를 작성했다 | 원본 Automation Test의 실제 assertion | 이번 공개본 제작 과정에서 해당 UE 테스트를 실행함 |

## 세 가지 회귀 사례

### 정확한 클래스만 풀에서 반환

일반 적만 넣은 풀에서 엘리트 취득은 null이어야 합니다. 반대로 엘리트만 넣은 풀에서 일반 적 취득도 null이어야 합니다. 상속 관계가 있다는 이유로 다른 런타임 타입을 재사용하지 않는 계약을 검사합니다.

### 중복 구매와 효과 적용 실패

한 번 구매한 revision으로 다시 요청해도 잔액이 추가로 줄어들지 않아야 합니다. 잘못된 오퍼 인덱스도 잔액을 변경하면 안 됩니다. 효과가 없는 잘못된 카드를 넣어 실제 적용 거부를 만들고, 차감한 돈과 오퍼가 보존되는지 검사합니다.

### 겹친 바닥에서 목표 표면 선택

합성된 2×1 그리드에 지면과 높은 데크를 배치합니다. Pawn의 발 높이를 기준으로 데크 표면을 선택하는지 확인합니다. 실제 월드 없이 입력 배열을 만들어 알고리즘의 경계 상황을 재현합니다.

## 공개본에서 수행한 검사

- 선택한 소스의 고정 커밋, 원본 경로와 줄 범위를 기록합니다.
- 코드 발췌가 해당 커밋의 원문과 일치하는지 SHA-256과 문자열 비교로 확인합니다.
- 저장소 내 Markdown 파일 링크의 대상 존재 여부와 코드 블록 구분자를 검사합니다.
- 허용한 텍스트 파일만 포함됐는지, 구매 에셋·설정·개발 이력이 섞이지 않았는지 검사합니다.

재현 명령: `python tools/verify_portfolio.py`. UE 설치가 필요하지 않으며 문서 링크·발췌 무결성을 검사합니다. 원본 저장소를 가진 유지보수자는 `--source-repo <path>`를 추가해 고정 커밋과 코드까지 대조할 수 있습니다.

## 실행하지 않은 검사

공개본에는 전체 C++ 의존 파일, `.uproject`, Blueprint, DataAsset 실물, 외부 플러그인이 없으므로 독립적으로 빌드하거나 게임을 실행할 수 없습니다. 이번 제작 과정에서는 Unreal 빌드·Automation Tests·PIE·패키지 실행·성능 측정을 하지 않았습니다. Mermaid는 GitHub가 렌더링하는 문서 다이어그램이며 게임 실행 결과가 아닙니다.

## 성능 결과를 추가할 때 필요한 조건

1,000개 적은 최악 상한 목표입니다. 실제 성능 자료를 추가하려면 커밋, 엔진 버전, CPU/GPU, 해상도, 패키지 설정, 활성 적 수, 접속 인원, 호스트·클라이언트 구분, 프레임 시간과 네트워크 지표, 측정 시간을 함께 제시해야 합니다. 현재 공개본에는 재현 가능한 원시 측정 자료가 없어 성능 그래프나 개선율을 넣지 않았습니다.
